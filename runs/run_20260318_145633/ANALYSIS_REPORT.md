## 三、问题诊断

### 3.1 核心问题：策略退化为RSU单一模式

**现象**:
- 99%+ 动作为RSU卸载
- Local和V2V探索几乎完全消失
- 策略熵从0.88崩塌至0.29

**直接后果**:
1. **RSU过载**: 所有任务集中卸载到RSU，导致队列拥塞
2. **资源浪费**: 车辆本地计算能力和V2V协作潜力未被利用
3. **探索停滞**: 策略陷入局部最优，无法发现更优解

### 3.2 根本原因分析

#### 原因1: RSU的结构性优势过于显著

**RSU优势**:
1. **计算能力**: 6 GHz × 4核 = 24 GHz总算力，远超单车辆 (1-1.8 GHz)
2. **稳定性**: 固定位置，无移动性风险
3. **通信**: 覆盖范围300m，带宽10 MHz (V2V为20 MHz但受距离限制)
4. **信任度**: RSU信誉度0.95，无失败风险

**车辆劣势**:
1. **计算弱**: 单车算力仅RSU的1/24 ~ 1/13
2. **移动性**: 速度10 m/s，存在链路中断风险
3. **V2V不确定性**: 邻居可用性动态变化，通信距离受限200m

**量化对比**:
```
任务完成时间估算 (假设1 Gcycles任务):
- RSU: 1G / 6G = 0.167s (计算) + 通信时间
- 车辆Local: 1G / 1.5G = 0.667s (4倍慢)
- V2V: 通信 + 0.667s + 链路风险
```

在当前环境配置下，RSU在绝大多数场景下都是最优选择，这是**环境设计问题**，而非算法问题。

#### 原因2: 奖励函数未充分惩罚RSU过载

**当前奖励设计**:
```python
W_TIME = 0.35      # 时间权重
W_ENERGY = 0.05    # 能耗权重
W_INTERF = 0.03    # 干扰权重
```

**问题**:
1. **时间主导**: 时间权重0.35远高于能耗0.05，智能体优先优化完成时间
2. **RSU队列惩罚不足**: 虽然RSU过载会增加等待时间，但分摊到单个决策的惩罚微弱
3. **能耗激励弱**: Local执行能耗最低，但0.05权重不足以抵消时间劣势

**数值示例**:
```
假设任务A:
- RSU卸载: 时间1.5s, 能耗0.01J → reward ≈ -0.35×1.5 - 0.05×0.01 = -0.525
- Local执行: 时间2.0s, 能耗0.005J → reward ≈ -0.35×2.0 - 0.05×0.005 = -0.700

RSU奖励更高 → 智能体选择RSU
```

即使RSU队列已有10个任务，增加的等待时间惩罚仍不足以让Local成为更优选择。

#### 原因3: Logit Bias修改未达预期效果

**本次修改**:
- `LOGIT_BIAS_RSU = 0.0` (去除RSU先验)
- `LOGIT_BIAS_LOCAL = 0.10` (增加Local先验)
- `LOGIT_BIAS_V2V_INIT = 0.10`

**实际效果**:
- 初期Local占比8.8%，确实有所提升
- 但200 ep后迅速降至0.2%，bias效���被价值函数覆盖

**原因**:
1. **Bias量级不足**: 0.1的logit bias在softmax后仅增加约10%概率质量，无法对抗RSU的结构性优势
2. **价值函数主导**: 随着训练进行，critic学习到RSU的高价值，actor的logit bias被价值梯度压制
3. **无退火机制**: bias固定不变，无法在探索-利用间动态平衡

#### 原因4: 熵系数提升反而加速收敛

**预期**: 提升熵系数至0.02应增强探索
**实际**: 熵从0.88快速降至0.29

**原因**:
1. **熵正则化的局限性**: 熵系数只能鼓励策略分散，但无法改变动作的相对价值
2. **RSU价值过高**: 当RSU的Q值显著高于其他动作时，即使有熵正则化，策略仍会收敛到RSU
3. **熵-奖励权衡**: 0.02的熵系数相比时间奖励权重0.35太小，智能体宁愿牺牲熵换取更高任务奖励

**数学解释**:
```
策略目标: max E[R] + α·H(π)
当 Q(RSU) >> Q(Local/V2V) 时:
即使 α=0.02，最优策略仍是 π(RSU) ≈ 1
```

#### 原因5: Critic学习率降低延缓但未阻止收敛

**修改**: `LR_CRITIC = 2e-4` (从5e-4降低)

**效果**:
- 训练更稳定 (critic loss波动减小)
- 但未改变最终收敛方向

**原因**:
- 降低学习率只是减缓收敛速度，不改变收敛目标
- RSU的结构性优势是环境固有的，慢速学习仍会学到相同结论

## 四、深层次问题：环境设计与算法目标不匹配

### 4.1 环境设计问题

当前环���配置下，RSU是**客观最优解**:

1. **算力差距**: RSU算力是车辆的13-24倍
2. **稳定性**: RSU无移动性风险，车辆有链路中断风险
3. **覆盖范围**: RSU覆盖300m，V2V仅200m
4. **任务负载**: 20车辆 × 平均1.5任务 = 30任务，2个RSU足以处理

**结论**: 在这种配置下，智能体学习到"全部卸载RSU"是**正确的策略**，而非算法失败。

### 4.2 算法目标与实际需求的矛盾

**算法目标**: 最小化任务完成时间 + 能耗
**实际需求**: 负载均衡、资源利用多样化、避免单点���载

**矛盾点**:
- 如果目标是最小化完成时间，RSU确实是最优选择
- 如果目标是负载均衡，需要显式建模RSU过载惩罚
- 当前奖励函数未明确表达"避免RSU过载"的需求
