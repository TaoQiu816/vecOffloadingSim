## 三、深度分析

### 3.1 为什么降低Critic学习率反而加速了RSU收敛？

#### 预期 vs 实际

**预期效果**:
- 降低Critic学习率 → Critic更新更慢 → 价值估计更保守 → 策略更新更谨慎 → 收敛更慢

**实际效果**:
- Run 2的RSU收敛速度**更快** (200 ep达到99% vs Run 1的800 ep达到77%)
- Run 2的动作多样性**更差** (熵0.29 vs 0.34)

#### 根本原因分析

**1. 熵系数提升的副作用**

Run 2将熵系数从0.012提升至0.02，本意是增强探索，但实际效果相反：

```
策略目标: J = E[R] + α·H(π)

当 α 从 0.012 → 0.02 时:
- 熵项权重增加67%
- 但RSU的Q值优势过大，即使增加熵正则化，最优策略仍是π(RSU)≈1
- 更高的熵系数反而加速了策略向"确定性最优解"的收敛
```

**原因**: 熵正则化只能鼓励策略分散，但无法改变动作的相对价值。当RSU的价值显著高于其他动作时，增加熵系数只会让策略更快地"确认"RSU是最优选择。

**2. Critic学习率降低的意外效应**

降低Critic学习率从5e-4到2e-4，导致：

- **价值估计更稳定**: Critic对RSU的高价值估计更快稳定
- **Actor更信任Critic**: 稳定的价值信号让Actor更快收敛到RSU
- **探索窗口缩短**: 在Critic还未充分探索其他动作时，价值估计已经稳定

**对比Run 1**:
- Critic学习率5e-4 → 价值估计波动更大 → Actor持续探索 → Local保持活跃

**3. 初始探索差异**

| 阶段 | Run 1 | Run 2 |
|------|-------|-------|
| 初期RSU占比 | 40.7% | 86.2% |
| 初期Local占比 | 55.7% | 8.8% |
| 初期熵 | 1.075 | 0.884 |

**关键发现**: Run 2在初期就已经偏向RSU (86%)，而Run 1初期更偏向Local (56%)。

**可能原因**:
1. **随机初始化差异**: 虽然种子相同(42)，但Git版本不同可能导致初始化差异
2. **早期经验影响**: Run 2早期就体验到RSU的高回报，强化了RSU偏好
3. **熵系数的反作用**: 更高的熵系数在初期反而加速了对"最优动作"的识别

### 3.2 为什么Run 2的性能反而更差？

#### 性能指标对比

| 指标 | Run 1 | Run 2 | 差异 |
|------|-------|-------|------|
| Episode奖励 | 0.139 | -0.028 | **-0.167** |
| 任务成功率 | 95.8% | 89.9% | **-5.9%** |
| 任务完成时间 | 1.35s | 1.57s | **+0.22s** |

**原因分析**:

**1. RSU过载问题**

Run 2几乎所有任务都卸载到RSU，导致：
- RSU队列拥塞
- 任务等待时间增加
- 部分任务超时失败

**2. 资源利用不均**

- Run 1: 77% RSU + 21% Local → 负载分散
- Run 2: 99.9% RSU + 0.1% Local → 单点过载

**3. 缺乏鲁棒性**

Run 2的单一策略在以下场景表现差：
- RSU临时过载时无法切换到Local
- 车辆距离RSU较远时仍强行卸载
- 简单任务也卸载RSU，浪费通信开销

### 3.3 训练指标对比

#### Critic Loss

- **Run 1**: 波动较大，持续学习
- **Run 2**: 快速收敛，后期平稳

**解释**: Run 2的低学习率让Critic更快稳定，但也限制了对新经验的适应能力。

#### Actor Loss

- **Run 1**: 持续波动，策略持续调整
- **Run 2**: 快速收敛，策略固化

**解释**: Run 2的Actor更快收敛到RSU单一策略，后期几乎不再更新。

#### KL Divergence

- **Run 1**: 平均0.005，策略更新温和
- **Run 2**: 平均0.003，策略更新保守

**解释**: Run 2的策略更新更保守，但这反而加速了向局部最优的收敛。

## 四、核心结论

### 4.1 参数调整的反直觉效果

| 调整 | 预期效果 | 实际效果 | 原因 |
|------|----------|----------|------|
| 降低Critic学习率 | 收敛更慢 | **收敛更快** | 价值估计更稳定，Actor更快信任 |
| 提升熵系数 | 探索更多 | **探索更少** | 无法改变动作相对价值，反而加速确认最优解 |

### 4.2 关键洞察

**1. 环境结构性问题主导一切**

无论如何调整超参数，只要环境配置不变（RSU算力13-24倍于车辆），智能体最终都会收敛到RSU主导策略。差别只是：
- **收敛速度**: Run 2更快 (200 ep vs 800 ep)
- **收敛程度**: Run 2更彻底 (99.9% vs 77.4%)

**2. 超参数调整的有限性**

在当前环境下，超参数调整只能影响：
- 收敛速度
- 收敛程度
- 训练稳定性

但**无法改变收敛方向**（都是RSU主导）。

**3. 多样性 ≠ 探索不足**

Run 1的21% Local占比不是"探索不足"，而是**找到了更好的负载均衡策略**：
- 简单任务Local执行
- 复杂任务RSU卸载
- 整体性能更优

Run 2的99.9% RSU占比是**过度收敛**，牺牲了鲁棒性和性能。

### 4.3 哪个训练更好？

**从性能角度**: **Run 1更优**
- Episode奖励: 0.139 vs -0.028 (+0.167)
- 任务成功率: 95.8% vs 89.9% (+5.9%)
- 任务完成时间: 1.35s vs 1.57s (-0.22s)
- 动作多样性: 熵0.341 vs 0.286

**从收敛角度**: **Run 2更快**
- 200 ep达到稳定 vs 800 ep
- 策略更确定 (熵更低)

**综合评价**:
- **Run 1是更好的训练结果**: 性能更优，策略更鲁棒，负载更均衡
- **Run 2是过度收敛的失败案例**: 虽然收敛快，但陷入局部最优，性能反而下降

## 七、总结

### 7.1 核心发现

1. **降低Critic学习率 + 提升熵系数 = 更快收敛到RSU单一策略**
   - 与直觉相反，但符合理论分析

2. **Run 1的配置更优**
   - 性能更好 (奖励+0.167, 成功率+5.9%)
   - 策略更鲁棒 (21% Local保持活跃)
   - 负载更均衡

3. **超参数调整的局限性**
   - 只能影响收敛速度和程度
   - 无法改变收敛方向（RSU主导）
   - 根本解决需要环境和奖励调整

### 7.2 关键教训

**1. 更高的熵系数不一定带来更多探索**
- 当动作价值差距过大时，熵正则化失效
- 反而可能加速向"确定性最优解"的收敛

**2. 更低的学习率不一定更稳定**
- 可能导致价值估计过早固化
- 限制对新经验的适应能力

**3. 性能指标比收敛速度更重要**
- Run 2收敛更快，但性能更差
- Run 1收敛更慢，但找到了更好的策略

### 7.3 最终建议

**短期**: 使用Run 1的超参数配置继续训练

**中期**: 实施环境调整（提升车辆算力，限制RSU资源）

**长期**: 重构奖励函数，显式建模负载均衡目标
